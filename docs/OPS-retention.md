# 継続率の計測（OPS）

再会カード・「おかえり」の効果を確かめるための集計。`scripts/retention.mjs`（PLAN 82）。

## 安全性

- 読み取り専用。書き込み・削除はしない。
- thoughts は `date` だけ、moods は ID（日付）だけをサーバーから取る。本文・タイトル・uid は取らず、出力にも出ない（人数と割合だけ）。
- `.env.local` の Admin 鍵が要る（`npm run backup` と同じ）。

## 実行

```bash
npm run retention                         # 全体
npm run retention -- --since 2026-11-01   # この日以降に始めた人／始まった途切れだけ（機能の前後比較）
npm run retention -- --json               # JSON で出す
```

`package.json` の `scripts` に次の行を足す（指揮官が反映）。

```json
"retention": "node scripts/retention.mjs"
```

## 定義

記録した日 ＝ `thoughts.date` ∪ `moods`（玉だけの日も1日に数える）。日付は Asia/Tokyo。開始日 D0 ＝ 最初の記録日。

| 指標 | 意味 |
|---|---|
| 1・7・30日後（ちょうど） | D0+N の日に記録がある人 ÷ D0+N が今日以前の人 |
| 1・7・30日後（N日以内） | D0+1〜D0+N のどこかに記録がある人 ÷ 同じ分母 |
| 途切れ | 記録の空きが3日以上（アプリの「おかえり」の条件と同じ）。1人が何回でも数える |
| 戻った率 | 戻った途切れ ÷（戻った途切れ ＋ まだ戻っていない途切れ） |
| 7日／30日以内に戻った | 途切れの開始日から次の記録までが 7日／30日以内の割合 |

まだ N 日たっていない人は分母に入れない（入れると低く出る）。

## 読み方の注意

- 人数が少ないうちは割合がぶれる。分母（`x/y`）を必ず見る。
- 再会カードの効果は `--since <公開日>` と全体の差で見る。ただし他の変更（手紙など）も同時期なら切り分けられない。
- ゲスト（匿名）も含む。30日で消える設計なので、30日後の値は低めに出る。
- 玉だけの日も数えるため、「書いた」より緩い継続率になる。
