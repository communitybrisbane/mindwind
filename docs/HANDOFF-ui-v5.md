### 1-1. 今回（2回目の審査の最終修正）で直したこと

1. **危機の言葉の判定が一言（quick）の新規保存だけだった（medium・憲法第8条）**：深掘りの答え、AI の上限に当たった日の日記、あとからの編集（`PUT`）、あとから深掘りで足した答えは AI を一度も通らないのに判定が無かった。`POST /api/thoughts` は kind を問わず本文と答えを判定、`PUT /api/thoughts/[id]` は変わった項目を判定して `crisis: true` を返す。記録タブ・`ThoughtModal`（編集・あとから深掘り）にも `CrisisNote` を出す（モーダルではボタンが「とじる」）。窓口の番号は `lib/logic/crisis.ts` の `HOTLINES` に一本化。
2. **深刻な週に手紙の生成が失敗すると窓口の案内が出ない（high・憲法第8条）**：refusal・max_tokens・使えない手紙・例外のとき、危機の週（その週の本人の言葉に危機の言葉がある週）は、作りかけを消してエラーにする代わりに**固定文だけの手紙**（`CRISIS_LETTER_PARAGRAPHS`・`model: "fixed-text"`）を保存して届ける。
3. **手紙のセーフティがプロンプト任せだった（medium）**：`applyLetterSafety()` で、危機の週は AI の出力から**引用を全部落とし**、窓口の案内（両方の番号）が無ければ固定文を足す。AI 自身が窓口を案内した手紙（＝AI が深刻と判断した）も引用を落とす。
4. **本文の「」『』を検証していなかった（medium）**：`>> ` の引用行だけでなく、本文の段落で「」『』に囲んだ 4 字以上の言葉がその週の記録（本文・答え）に無ければ、その**段落ごと落とす**（言い換えを本人の言葉として出さない。Q だけにある言葉も通らない）。段落が全部落ちたら使えない手紙として扱う。
5. **画面を閉じると手紙の生成が最後まで走る保証が無かった（medium）**：`POST /api/letters/current` は `202 generating` をすぐ返し、生成と保存は **`after()`** で続ける。画面（`useLetter`）は GET を 4 秒おきに取り直して受け取る。途中の文は流さない（検証前の文を見せない）。この画面が POST したあとに `none` に戻ったら失敗とみなしてエラー文を出す（自動で再 POST しない。次に開いたときにもう一度）。`LetterStreamEvent`・`already_generating` は廃止。
6. **止まった生成の枠が戻らない（medium）**：生成中ドキュメントに `usageDate` を持たせ、6 分超で止まったものを作り直すときに前の枠を `refundQuota()` で戻す。届いている・生成中のときは枠を使わない（先に状態を見てから消費）。
7. （low・ついで）`ndjsonResponse`：切断後の `close()` の例外を握る（相談で使用）。

### 1-2. 第1版（1回目の審査）で直したこと

1. 相談が新しい記録を見ていなかった（high）：`lib/ai/rag.ts` をチャンク検索に切り替え、参考ブロックを「本人の言葉＋日付」に。0件なら「見つからなかった」の一行（憲法第4条2項）。
2. 記録を消しても相談の履歴に写しが残っていた（medium・憲法第13条）：`DELETE /api/thoughts/[id]` が先に相談の refs と手紙の引用を伏せる（`lib/db/scrubDeleted.ts`）。
3. アカウント削除で端末の下書きが残っていた（medium）：`mindwind:` の localStorage と sessionStorage を消す（`mindwind:prefs` は残す）。
4. 本番の設定もれで費用がむき出しになる（medium）：`[production-config]` の警告（止めない）。`docs/SECURITY-SETUP.md`「公開前チェック」。
5. 相談の失敗で空スレッドが残る（medium）：この呼び出しで作ったスレッドを消す。
6. 記録の編集の競合（medium）：`409 conflict`。

## 6. 既知の問題（直していないこと）

### 危機対応・AI まわり
- **危機の言葉の見逃し（low）**：固定リストなので婉曲な表現は拾えない。「楽になりたい」「終わりにしたい」「生きていたくなかった」「死にたかった」「眠ったまま起きたくない」は false。足すなら誤検知（「もう楽になりたい、週末だ」など）と合わせて `crisis.test.ts` の「拾わない」一覧で決める。
- **深掘り・相談の危機対応はプロンプト任せ**：追記に「セーフティが優先」の一文が無い（§3）。相談の RAG は、危機の言葉を含む記録も本人の言葉のまま Opus に渡す（参考記録として本人に見せるのは設計どおり。AI の返答は共通部のセーフティに従う前提）。
- **一言の画面で保存の応答本文が読めなかったとき（low）**：保存は成功しているのに `crisis` が拾えずホームへ進む。`detectCrisis` は純粋関数なので、画面側で保険に呼べる（未実装）。
- **手紙の引用の長さ（low）**：`>> ` の引用は最短 2 字で、上限（60 字程度）はコードで見ていない。本文の長さ（250〜400 字）も未検証。
- **手紙の失敗の再試行に上限が無い（low）**：失敗は枠を返すので、失敗が続く週は日次の枠に関係なく Opus を呼び直せる（1 回の開き直しにつき 1 回。自動では再試行しない）。

### コード・テスト
- **`letterStore` のトランザクション分岐のテストが無い（low）**：`beginLetter`（ready／generating／stale の作り直し・`staleUsageDate`）・`saveLetter`（genId 違いの拒否・消えた記録の引用を伏せる）・`discardLetter` は Firestore のフェイクが要る。純粋関数（`decideBegin`・`maskMissingRefs`・`toLetter`）だけテスト済み。
- **`ThoughtModal` の Esc 用 `useEffect` の依存（low）**：`useQuickDeepDive` の戻り値をそのまま依存に入れているので、描画のたびにリスナーを付け外しする。動作は正しい。
- **移行前の記録には 6 項目の成形文が渡る**：チャンクが1つも無い人のフォールバックでは、`rawText` が無い古い記録は旧6項目を本人の言葉の代わりに渡す。59 の移行を済ませれば解消。
- **ボタンの最小サイズ（low）**：記録タブ上部のしおりチップ（30px）・月／年の切り替え（46px）・今日の玉（40px）は 54px 未満。プロトタイプと同じ大きさなので、厳密にするかは本人判断。
